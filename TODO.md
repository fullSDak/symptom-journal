# Symptom Trail — approved outcomes

- [x] **Symptom capture:** Patients can quickly log symptoms as text or by voice, including what they noticed, when it began, when it resolved, whether it is ongoing, and optional severity and everyday impact. Dictation requires explicit consent if the browser may use an external speech service; voice recording works independently where supported.
- [x] **Photos and timeline:** Patients can attach optional photos to entries, record when visible changes appeared or changed, and browse entries and attachments chronologically, including intermittent and recurring experiences.
- [x] **Appointment summary:** Create an appointment-ready summary organizing selected symptoms, dates, changes, impact, and selected photos; the patient can review and edit before choosing how to share. No automatic clinician notification.
- [x] **Patient context:** Let patients include relevant history, test results, medications, and questions for their provider without turning the information into a diagnosis.
- [x] **Optional ESR note:** Support a patient-confirmed note about a reported hemoglobin disorder and possible limitations of ESR interpretation, using cautious sourced language and never making a diagnostic claim.
- [x] **Inclusive, safe care:** Use inclusive language acknowledging visible symptoms may appear differently across skin tones without making assumptions based on race or ethnicity. Clearly state that the tool does not diagnose or replace urgent medical care.
- [x] **Privacy and prototype:** Explain where information is stored; store records on this browser/device only, disclose data-loss risks and external speech recognition, and use fictional examples. This demonstration is not ready for real protected health information.
- [x] **Delivery:** Validate app build and behavior, render in iPhone-sized layout, save a Manus checkpoint, and do not publicly publish without user approval.
